# 持续任务与上下文窗口（schema v3）

Confucius 的研究任务持有稳定 ID、来源、成果、草稿和执行记录。Native 的上下文窗口可以替换；替换窗口不调用模型生成会话摘要，也不重建当前 TurnLoop 的预算。旧的 `task/compact`、`session/compact` 作为兼容入口执行同一换窗流程。

这个设计参考 Codex 的实验路径，并不假设所有 Codex 会话已采用该机制：[启用改动](https://github.com/openai/codex/pull/42385)、[固定版本的换窗实现](https://github.com/openai/codex/blob/459a79eb85400af759e9220c7bafb4429ae07516/codex-rs/core/src/compact_token_budget.rs)。Confucius 不修改 Codex 的实验配置。

## 数据与边界

数据位于 Zotero 数据目录的 `confucius/`：

- `state.json`：schema v3 任务、活动窗口、执行检查点和按任务保存的草稿／会话引用。
- `history/<taskId>/index.json`：窗口、不可变历史条目、工作笔记版本与删除标记。
- `history/<taskId>/windows/<windowId>/<itemId>.txt`：宿主可见的原始输入、工具执行参数和完整结果。结果在提供给模型的截断之前保存。
- `history/<taskId>/notes/<name>_<revision>.txt`：任务工作笔记。写入只针对当前任务，独立于用户记忆与知识库的审查流程。
- `logs/sessions/`：保留旧 Markdown 日志作为兼容资料。

历史正文按条目独立存放。读取返回有界片段和 `nextOffset`，检索返回稳定的任务／窗口／条目 ID 以及文献来源。检索在本机执行，不将所有任务历史预先放入模型请求。显式引用的任务优先；默认仍可按相关性检索其他未删除任务。

Native 记录原始用户要求与模型实际输入；图片的像素仅供当次调用，持久内容使用工具返回的 PDF／页码等来源锚点重新读取。外部引擎窗口标记为 `runtime-partial`：只能保存 CLI 实际暴露给宿主的材料，无法补出其内部消息或未报告的工具结果。

## Native 换窗

`WindowContext` 在每次模型请求前计算完整消息、系统指令、工具定义和附件的容量估算，并保留输出空间和安全余量。中文使用更保守的字符估算；若提供实际输入用量，后续估算会校准。统计显式区分 `reported`、`estimated`、`unknown`。

图片单独预留容量，不把 Base64 传输字节当作文本 token；不同模型的图片用量仍需通过实际回报校准。未配置输出上限时，普通 Native 请求默认预留并设置 4096 token，预设成果交付使用 6000 token。

达到容量预警时提醒保存工作笔记。模型调用 `new_context`，或下一请求无法安全容纳时，在工具调用组完成、审批已解决后执行：

1. 持久保存完整历史与执行检查点。
2. 检查新窗口基础输入是否可以容纳。
3. 持久安装新窗口；保留当前原始要求、任务来源、成果引用以及历史／笔记入口。
4. 在原 TurnLoop 中继续执行，保留迭代计数与工具执行记录。

写盘失败会保留旧窗口；基础输入超限会明确失败，不循环换窗。写入工具抛出异常或返回内部错误时，将其结果视为未知，保留执行记录并阻止自动重试；工作流的自动重试也遵守这一规则。此类任务需要先在 Zotero 中核验写入结果，不能用“继续”绕过未知结果保护。

每次模型请求前先持久记录已消耗的迭代。停止／重启后“继续”承接检查点中的迭代数、工具预算与预设阶段；已完成且参数相同的写入复用原执行结果。HTTP 将取消报告为普通网络错误时，仍以用户停止信号为准。手动换窗也保留这些计数和执行记录。

## 宿主接口

| 接口                       | 用途                                               |
| -------------------------- | -------------------------------------------------- |
| `context/search-tasks`     | 按标题搜索未删除任务，分页返回稳定 ID、时间、状态  |
| `task/new-context`         | Native 在空闲安全边界换窗；旧 compact RPC 保持兼容 |
| `task/history`             | 列出条目；传入 `windowId`、`itemId` 后分页读取原文 |
| `task/draft`               | 读取／持久保存当前任务的文本草稿和结构化会话引用   |
| `history_list/search/read` | Agent 按需列出、搜索、读取历史                     |
| `notes_list/read/write`    | Agent 维护当前任务的工作笔记                       |
| `new_context`              | Native 请求在下一安全边界换窗                      |

Native 与 Codex／Kimi 的任务 MCP 使用同一个 `TaskHistoryToolProvider`。外部 CLI 自己管理上下文窗口；Codex 的实际用量与 compaction 通知映射为宿主状态。Kimi 未提供窗口用量时保持未知，不使用 Native 的容量配置计算百分比。

引用其他任务不会运行、修改或合并它。历史中的指令、权限与审批均作为资料读取，不授予当前任务权限。预设任务的来源边界同时应用于历史搜索和直接条目读取，不能通过猜测历史 ID 绕过。旧日志的全局查询也排除已删除及孤立任务；原文件仍保留。

历史来源包含工具参数、完整结果与回读资料中实际出现的文献引用。范围内检索要求条目的全部已知文献来源都在范围内；没有文献引用的回答不会仅因任务选中过某篇论文而被标为该论文的证据。

## 迁移与恢复

首次升级保存 `state.json.v2-backup`，再迁移现存任务的消息、事件及日志。相同角色与文本去重，导入 ID 确定，已完成导入有标记，可重复启动。旧记录标为 `legacy`、`incomplete`，不补写已截断或缺失的内容。仅剩 Markdown 文件而无现存任务的记录不进入全局检索。

任务删除写入持久删除标记，移出检索；已保存的会话引用显示来源不可用。任务不会因为超过旧的 60 条上限而被隐式丢弃。

## 产品与验证

共享样式、任务列表、来源选择器、输入逻辑、活动流更新和成果正文分别位于 `workspaceTheme`、`workspaceTasks`、`workspaceSourcePicker`、`workspaceComposer`、`workspaceActivity`、`workspaceReading`。保持暖白／深褐品牌，增加语义颜色、统一焦点状态、任务搜索与状态分组。会话引用以标签呈现；输入支持多行、Enter 发送、Shift+Enter 换行，并避开输入法组合事件。

活动流用稳定条目键保留未改变的 DOM、展开状态与焦点。用户阅读上方历史时，流式更新和新增审批不强制滚到底部。任务切换与窗口／侧栏切换保留草稿、引用和阅读位置；已有任务的草稿同步持久保存。成果按文件／修订版本记忆滚动位置，关闭阅读层后恢复原控件焦点。

自动测试覆盖完整长结果分页、中文检索、同名任务、来源限制、删除与重启、工作笔记写盘失败、连续换窗、预算连续性、审批停止、未知写入和基础输入超限。Zotero 10 独立开发配置中另用本地测试模型验证 11 次请求／3 次换窗／10 条工具执行记录，以及三种后端通过宿主接口读取同一历史正文。实际外部 CLI 模型会话不属于这个本地模拟验收。

旧数据实测从消息、事件和 Markdown 日志去重导入 4 条记录；再次启动仍为 4 条，备份与原文件一致，孤立日志不进检索。另一次停止／换窗／退出／重启／继续的实测保留第 2 个窗口，迭代从 2 接续到 4；模型再次请求同一笔记写入后，笔记仍只有 1 个版本、1 条执行记录。

验证命令：`npm test`、`npm run typecheck`、`npm run build`。实机预览使用 `npm start`，推荐独立 Zotero profile 与 dataDir。
