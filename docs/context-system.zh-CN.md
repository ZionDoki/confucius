## 长任务如何继续

模型一次能使用的上下文有限。Confucius 会在本机保存原始对话和工具记录，
需要换窗时，把当前要求、来源、进度、下一步和部分证据带到新窗口。

换窗保留报告、写入回执、审批和已消耗额度，等待工具与审批到达安全边界后执行。
准备或保存失败时，旧上下文及可恢复状态仍保留。

信息完整的交接不增加整理模型调用；缺少信息时最多补充一次，
与研究记忆提取和蒸馏共用每个用户轮次两次维护请求额度。
外部运行方式可能还有未向插件报告的内部调用或用量。

## 核对实际覆盖范围

可以问：“列出每篇来源的处理情况、已经读过的内容和下一未读页。”

搜索命中、工具返回页面和完成事实核验是不同状态。
Agent 可以回读归档片段，但重要结论仍需核对原文；
绑定一个集合，也不代表读过其中所有文章。

## 历史保留多久

| 状态   | 默认规则                                                        |
| ------ | --------------------------------------------------------------- |
| 近期   | 目标为最近 10 个已结束任务、30 天、50 MiB；超出后转入本地归档。 |
| 已归档 | 仍可搜索、读取和导出；默认保留目标为 90 天、500 MiB。           |
| 已清理 | 原始正文不可用，保留的状态说明不能恢复正文。                    |

实际读取归档正文或继续任务会续期；搜索、后台维护和诊断导出不会。
活跃任务、恢复工作和未决操作可保护相关记录，因此容量可能暂时超出目标。

**历史自动清理**与**自动维护普通记忆**独立。
关闭清理会保留归档；记忆提取是否成功，都不能单独决定删除原始历史。
报告、Zotero 原生数据和权威写入回执不属于可随意清除的历史缓存。

划线旁支在同一清理开关下使用自己的近期与归档规则，详见[划线询问](selection-questions.zh-CN.md)。

## 任务停住时

- **交接资料不足：**让 Agent 保存当前发现、下一步和来源位置，再继续。
- **维护额度耗尽：**已有材料仍在，不要反复要求换窗。
- **上下文容量不足：**减少输入或改用更大上下文模型；增加步骤次数不会扩大容量。
- **遗漏早期要求：**重新指出要求，让 Agent 回读相关历史与原文。

历史不是永久备份，需要长期保留的资料请[导出并备份](tasks-and-data.zh-CN.md)。
