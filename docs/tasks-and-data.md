# 任务恢复、文件与更新

## 启动后添加论文

0.4.3-beta.1 支持在没有选中文献、没有打开 PDF 时先选择研究模式，再在输入框输入 `@`
并从列表中选择文献。选中的条目会成为任务来源，无需重新创建任务；也可以先添加
文献再切换模式。这个流程适用于 Native、Codex、Kimi，以及 Agent 和 Plan 模式。

单篇论文模式需要一篇来源，对比、综述等模式需要至少两篇文献或一个集合／已保存
搜索；针对选段的操作仍需要实际的 PDF 文字选区。来源挂载失败时会保留输入和待添加
文献，再次发送会重试挂载。仅手打 `@[标题]` 不会绑定文献，需要从 `@` 列表中选择。
这项修复属于 0.4.3 的 Beta 预览，0.4.2 的普通安装包不包含这些改动。

## 请求重试与继续

以下功能从 0.4.3-beta.2 开始提供。请在更新设置中开启“接收测试版更新”，
安装后重启 Zotero。0.4.2 和 0.4.3-beta.1 安装包不包含这些完善。

模型请求超时、网络中断或暂时性服务错误会自动重试，每个请求最多尝试三次。
通常等待 1 秒、2 秒；服务端指定等待时间时最多等待 30 秒，停止按钮可以取消等待。
流中断后的失败片段不会拼入正式回答，残缺工具调用不会执行。鉴权、参数错误、
用户取消和审批拒绝不会自动重试。Codex 自行重试时仅显示进度；Codex/Kimi 的执行
终止且错误可恢复时，Confucius 最多恢复两次，先结束旧执行并核对写入记录。

耗尽后显示“进度已保留”，可以点击“继续”。如果某项写入结果未知，先核对 Zotero
中的实际结果；已成功或已经删除的标注不会自动重建。标题生成和记忆提取失败会在
任务末尾显示单独的重试入口，已经完成的主体成果保持完成状态。

当前源码的后续改进（尚未发布）：重试状态显示在任务的 loading 动画旁，包括
当前次数、等待时间和连接恢复状态。思考、工具执行和重试期间都会保留 loading，
直到本轮完成或中止。外部引擎超过 5 分钟没有模型或工具活动，或断流重试后
超过 2 分钟没有进展，会进入有次数上限的恢复；等待用户审批时不计入这个超时。
恢复会先结束旧执行、核对保存回执，再补齐报告等剩余成果。

## 继续未完成的任务

停止任务后，可以点击“继续”或发送“继续”，接着处理当前请求。已保存的成果和
批注仍然保留，继续不会重置已消耗的步骤和工具调用额度。

Zotero 意外退出后，正在执行的任务会恢复为中断状态。重新打开任务，查看已有
成果和待办，再显式继续。重启本身不会自动重新执行任务。批量批注部分成功时，
Confucius 保留成功项并处理剩余项；已提交后被手工删除的批注不会自动重建。

长任务会按需读取历史材料，Codex 和 Kimi 还使用各自的上下文管理。保存了历史
不等于模型每次都能正确回忆：0.4.0 的 Native 实测曾在长上下文、重启后遗漏早期
要求，首次文献报告也出现过事实错误。恢复后请核对关键约束、引用和数字；有遗漏时
明确提醒模型回查任务历史及原文。Kimi、Codex 在本轮单篇论文任务中通过了对应检查，
这不代表所有模型、文献和任务都具有相同表现。

## 阅读与批注

可以直接要求 Confucius 在 PDF 上高亮原文并添加评论，指定页码、数量和颜色。
批注审批会显示具体原文；确认后写入 Zotero 的原生 PDF 批注。文本页中的可选
片段带有原生位置，模型无需重新抄写整句来定位。部分条目定位失败时，成功项保留，
后续只处理未完成项。

“本次任务允许”会在当前任务中记住对该工具的授权，后续调用同一工具无需重复确认；
其他写入工具仍按各自的授权设置处理。保存任务内的阅读报告、草稿和成果文件无需
Zotero 写入确认；把内容写入文库笔记或 PDF 批注时才按对应工具申请授权。

若保存报告时提示成果 ID 无效，应让模型新建本任务的成果，或使用本任务已保存成果
的 ID 继续修改。重新授权或修改任务 ID 无法修复成果 ID 冲突，其他任务的报告不会被覆盖。

回复、批注评论和报告遵循设置中的界面语言，论文原文引文保留原来的语言。
精读报告先保存草稿，再回查原文和已经保存的批注；这一步不能保证所有事实都正确，
仍需核对重要数字的分母、比较范围和条件。扫描页、OCR 及跨页句的定位可能受限。

工具执行时，过程说明单独折叠显示，最终回复保留结论。读取 PDF 和写批注会优先
复用已打开的阅读器，后台初始化其他页面，减少切换窗口。

## 标注批次与颜色

同一任务聊天共用一个批次，追问、继续、重试和切换 Agent 均沿用。新建任务或分支
任务会创建新批次。批次名称取首次请求的简短摘要及短 ID，标注标签还显示批次创建
日期；后续修改任务标题不会改变这个名称。

任务开始时，已绑定 PDF 的标注颜色会被冻结；后来加入的 PDF 在加入时冻结。
新增标注不能使用这些已有颜色，冲突时自动换色。同一任务可重复使用已选颜色，
审批预览、保存回执和成果图例以最终颜色为准。如果颜色记录无法读取，暂停新增。

可以要求任一 Confucius Agent 修改其他任务／Agent 创建的 Confucius 标注，或删除
它们。支持修改评论，以及在原 PDF 内重新选择高亮／下划线原文；图像标注只能改
评论。修改保留原 key、颜色、批次、创建来源与创建时间，并记录最后修改时间。
预览后发生人工修改时，旧预览会失效，需要读取当前内容后再提交。

PDF 阅读器工具栏的“标注批次”提供“全部”“当前任务”“选择批次”。历史批次可
多选，也可选择“原有标注”。筛选同时作用于页面和标注侧栏，并与阅读器原有的
搜索等条件取交集；空结果不会删除数据。每个 PDF 保存自己的筛选选择，当前任务
模式随 Confucius 中选择的任务切换。

无法追溯批次的旧标注统一为“原有标注”，不会猜测批次、来源或创建时间。
只有已有宿主回执明确证明由 Confucius 创建时，旧标注才允许 Agent 修改或删除。
伪造或修改标签、颜色、作者名不会赋予权限。升级后继续旧任务只为后续新增标注
建立批次，旧标注不追溯归入新批次。删除聊天不删除标注的独立归属记录。

## 上下文、记忆与清理

以下为当前源码的重构行为，尚未发布。近期对话、工具结果和工作笔记用于继续工作；
较旧的内容经过提炼后只保留有限的长期记忆。普通短对话不再固定触发额外提炼。

默认保留最近 10 个已完成任务的原文，最长 30 天、合计最多 50 MiB。超限后排队
提炼最旧材料，先保存并校验提炼结果，再清理原文、工作笔记旧版本和重复日志。
每个用户轮次最多进行两次提炼请求，重试也计入；未处理完的批次延后。运行中、
未完成或仍有待确认操作的任务，以及提炼／保存失败的批次暂不清理，因此这些情况下
可以暂时超过保留目标。清理中断后会继续，旧任务会显示“原文已清理”。

长期记忆最多 200 条、正文约 16k tokens。普通记忆 90 天未被 Agent 主动读取就可
清退；容量不足时先清过期内容，再淘汰最久未使用的普通记忆。搜索命中、提示词自动
读取、后台合并和打开记忆列表都不会续期，也不会自动置顶。创建和迁移会启动保留期，
不会伪装成“主动读取”。

在设置中选择“自动维护普通记忆”后，Agent 可以保存和更新工作记忆。明确要求保留
的内容进入保护提案；在任务末尾或知识库的记忆列表中点击 `√` 批准，或 `×` 拒绝。
受保护内容的修改、删除及取消保护均需确认。记忆列表显示最后主动读取时间，并提供
保护与清除操作。保护内容也占容量；保护内容占满时停止新增，需手动整理。

关闭自动记忆会停止自动新增和模型提炼，保留工作笔记与主动检索；尚未提炼的旧原文
暂缓清理。普通记忆已有的过期和容量规则仍然适用。升级保留显式关闭的选择，来源不明
的旧记忆默认保护，旧搜索次数不作为真实使用记录。

模型通过 `context_search` 查少量片段，通过 `context_read` 分段读取，使用
`context_save` 保存工作状态。通常先检索当前任务、关联任务和适用记忆，必要时
扩大范围或翻译查询。原文已清理的引用会明确报告不可用，不会编造旧内容。

Native、Codex、Kimi 均可按需使用 `new_context`，也可在上下文详情中手动切换。
保存的成果、写入回执和累计额度继续生效，换上下文不会重做已完成的写入。
历史材料只是证据，不能作为新任务的指令或授权。外部引擎未提供的内部上下文和
实际用量仍显示未知；主机可见输入的估算不等于完整引擎用量。

用户保存的报告、知识库、Zotero 文库及导出文件不属于可自动清理的历史缓存。
需要长期保存的结论应明确保护或保存为报告／知识库条目。

## 持续修订研究报告

0.4.3-beta.1 的精读结果合并为一份报告：标注原文、解释和保存结果放在附录，末尾提供
“导读 Map”，用“问题 → 方法 → 证据 → 边界”解释论文思路。默认不单独创建标注
清单文件；需要独立清单时可以明确提出。已保存的旧报告和标注成果仍可阅读。

正文、摘要和导读中的来源组件可以点击，跳转到对应 Zotero 条目、PDF 物理页或
已有标注。只有摘要可用的相关文献会注明这一限制；没有可靠页码时只定位到条目。
旧报告里的纯文字页码不会自动变成有证据支持的引用，可以在同一任务中要求补齐
来源链接。以上新增能力属于 0.4.3 的 Beta 预览，0.4.2 的普通安装包不包含这些改动。

报告开头提供“一分钟速读”：研究问题、核心方法、主要结论和最重要的适用条件。
摘要就在报告正文中，后面接方法说明、带原文页码的关键证据和局限，方便先抓住
论文主旨，再按需要回查细节。报告和修订说明遵循设置中的语言。

在同一任务中可以继续要求“核对这个数字，并同步修正开头摘要”或“补充方法的
适用条件”。Confucius 会更新原来的报告，保留未涉及的内容、引用和历史版本；
打开该成果即可查看修订，无需在多份报告之间找最新版。

点击报告后会打开独立窗口，可以拖动、缩放、最小化并与 PDF 并排阅读。关闭
Confucius 聊天窗口或切换任务后，报告仍然保留；同一报告再次打开会回到已有窗口，
不同报告可以同时打开。使用系统标题栏的关闭按钮或 Ctrl+W 关闭报告，不另设内置
叉号。退出 Zotero、停用插件或删除对应任务时，相关报告窗口会关闭。

窗口默认跟随最新版，Agent 保存修订时保留当前滚动位置；选中文字时暂缓更新正文。
左上角的版本菜单可以查看历史版本，选定后会保持该版本，直到主动返回“最新版”。
报告沿用设置中的语言、字体、字号和行距，正文中的来源链接可回到 Zotero 原文。
“写回 Zotero…”的内容预览和最终确认也在报告窗口内完成；取消或关窗会撤销尚未
确认的请求，已经确认的写入继续完成。

精读复核仍需回查论文和实际保存的批注。报告已准确时可以直接结束复核；有错误时
只提交必要的修改。若报告在复核期间发生变化，或待修改的文字出现多次，整批修订
会停止并要求模型读取当前内容后重新定位，避免覆盖后来保存的修改。

这些能力从 0.4.2 开始提供，旧安装包需要先升级。

## 数据保存在哪里

| 内容                                                     | 保存位置                                                 |
| -------------------------------------------------------- | -------------------------------------------------------- |
| 任务状态、历史、成果版本、标注归属／批次、提案和操作记录 | 本机 Zotero local profile 的 `confucius/runtime-v1/`     |
| 研究记忆                                                 | `<Zotero 数据目录>/confucius/memory/` 中的 Markdown 文件 |
| Zotero 笔记、PDF 批注和附件                              | 由 Zotero 文库管理                                       |
| 导出的报告                                               | 导出时选择的位置                                         |

设置中的运行时存储路径显示当前实际目录。备份研究工作时，需要同时保留 Zotero
文库和 Confucius 的本机运行时目录；只同步文库不能在另一台电脑恢复完整任务。
知识库里尚未点击保存的编辑草稿只存在当前界面中，退出应用后不会保留。

从 0.3.x 升级时，Confucius 会将旧任务运行数据迁移到本机 profile，并校验迁移结果。当前源码会在维护时清除已验证且没有变化的旧任务／日志副本，
用户成果不在此清理范围。新版写入不会反向同步回旧目录，直接降级不能恢复新版期间的全部进度。
升级前完成备份，安装后重启 Zotero，再检查原有任务和成果。

## Windows 与 WPS 云盘

0.4.0 已在 Windows 11、Zotero 10.0.1 实测本地长路径、文件占用后的恢复，以及
WPS Cloud 本地同步目录中的文件读写和占用恢复。Confucius 的任务运行数据仍保存在
本机 profile。

本轮没有验证 WPS 云端同步完成、断网重连、多机冲突、虚拟盘，或把整个 Zotero
数据库放进 WPS 云盘。使用本地同步目录时，先确认要读取的 PDF 已下载到本机；
这些测试结果不能作为整个文库可在云盘上稳定运行的保证。

## 更新与 Beta

打开 **Confucius 设置 → 更新**，点击检查更新。Confucius 自行获取发布信息、
比较版本并校验下载包；检查不依赖 Zotero 的全局自动更新开关。

- **接收测试版更新**关闭时，只接收稳定版；打开时，同时比较稳定版与 Beta。
- 已安装 Beta 也可以升级到同版号的正式版，例如 `0.4.0-beta.1 → 0.4.0`。
- 关闭 Beta 开关不会降级，显式选择在重启和升级后保留。
- **自动检查更新**独立保存：启动后约 30 秒检查一次，之后每 6 小时检查。
  下载和安装仍需要点击“下载并安装”。
- 网络失败或校验失败会显示错误；恢复网络后可重新检查。

0.4.0 引入了这个独立更新器。如果旧插件检测不到新版本，请从
[最新正式版](https://github.com/ZionDoki/confucius/releases/latest)下载 `confucius.xpi`，
通过 Zotero 的插件管理页面手动安装一次，然后重启。

## 导出诊断报告

任务页或任务列表的 `···` 菜单提供“导出诊断报告”。报告保存为可离线打开的 HTML，
可以搜索事件、查看成果版本，并下载对应 JSON。导出不会调用模型。

报告包含仍保留的任务正文和引用材料，并对已识别的凭据脱敏。已提炼清理的原文不会重新恢复。分享前检查其中的研究内容。
外部引擎未公开的内部请求与上下文无法导出，旧任务已经丢失的事件也无法重建。

当前源码还增加了模型输出、公开推理摘要和任务结果摘要（尚未发布），可直接查看
保存的批注、缺失成果、重试错误和重复读页情况。“导出问题”只反映读取诊断数据
时的错误，执行中断会列在“任务结果与异常”。没有推理文本不代表模型没有思考；
累计 token 用量也不等于当前上下文长度，缺少缓存细分时不能据此计算实际费用。
